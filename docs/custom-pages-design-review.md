## 设计问题与优先顺序

1. 音源插件：原来顶部导入图标与列表主按钮重复；所有插件同等强调，卡片偏重；运行时术语和技术说明占据主要空间。以设置类页面为参照，使用圆角字体、轻量卡片、明确的导入区和收纳后的次要操作。
2. 在线详情：当前主要是标题、播放按钮和歌曲列表，缺少原专辑/歌单页面的封面与元数据层级。优先复用本地歌单详情的头部布局，展示封面、平台、标题、歌曲数量及简介；共用歌曲行与更多操作。
3. 下载管理：已有摘要卡和圆角列表，主要问题是下载状态混在同一列表。建议增加“进行中 / 已完成 / 失败”筛选，将进度、速度和重试动作放到对应状态，而不是增加更多卡片装饰；保留已有批量操作菜单。
4. 在线首页：已使用 LibraryHeaderScaffold、渐变与圆角标题，比纯 Scaffold 页面更贴近原应用。优先统一封面比例、标题行数、平台徽标、加载/空/失败状态，不需要重新设计整个导航。

通用规则：沿用 MaterialTheme 动态配色与原有 GoogleSansRounded 字体；页面边距、标题层级、卡片圆角按已有组件统一；主要动作可直接看到，删除和来源编辑收进菜单。设置管理页面与音乐内容页面分别对齐各自已有模板。

## 本轮已落实到音源插件页

- 居中圆角字体标题；主题色导入区；链接导入和本地文件两个明确入口。
- 已安装数量、轻背景插件卡、描述、启用开关；“正在使用”状态。
- 每个插件支持检查更新；更多菜单支持修改更新链接与删除。
- HTTP(S) 直链下载，记录来源；本地导入的插件可补填来源。
- 检查远端脚本内容是否变化，展示版本和来源后由用户确认更新。无版本号或版本号未变时也可以发现内容变化；不将内容变化误称为语义版本升级。
- 导入/检查不执行脚本；更新保留插件 ID、创建时间和启用状态。已启用插件更新加载失败时保留旧数据库记录并尝试恢复旧运行实例。
- 下载限制 9 MB、30 秒总超时，拒绝明显网页响应；取消操作会取消 HTTP 请求。
- 数据库 50 → 51 新增可空来源字段，兼容已有插件；插件备份直接序列化实体，因此来源随备份保留，旧备份的来源为空。

## 后续界面调整（当前范围）

按用户要求，本轮仅继续修改音源插件与下载管理，在线首页和在线歌单/榜单详情暂不改版；此前的 QQ 推荐加载修复保留。

- 下载管理：圆角字体标题、主题色摘要卡；全部/进行中/已完成/待处理筛选并显示数量，失败和取消归为待处理；筛选无结果时可返回全部。歌曲名与歌手分行，下载百分比可见，排队使用不确定进度。保留直接取消/重试，删除移至行内更多菜单。

- 下载筛选文案提供默认英文与简体中文资源。尚未进行设备端视觉验证。
